## 2. 修改 `models.py`

增加请求和响应模型：

```python
from typing import Literal

from pydantic import BaseModel, Field


class LogAnalyzeRequest(BaseModel):
    log_text: str = Field(
        min_length=1,
        max_length=10000,
        description="待分析的错误日志",
    )


class Evidence(BaseModel):
    log_fragment: str
    explanation: str


class ErrorAnalysis(BaseModel):
    error_type: str
    severity: Literal["low", "medium", "high"]
    confidence: Literal["low", "medium", "high"]
    possible_causes: list[str]
    suggestions: list[str]
    evidence: list[Evidence]


class LogAnalyzeResponse(BaseModel):
    success: bool
    data: ErrorAnalysis | None = None
    message: str | None = None
```

这里的核心是：

```text
请求模型：限制输入
响应模型：限制输出
```

## 3. 新建 `api.py`

```python
from fastapi import FastAPI, HTTPException

from log_analyzer import analyze_log
from models import LogAnalyzeRequest, LogAnalyzeResponse
from prompt_eval import validate_analysis, validate_business_rules


app = FastAPI(
    title="Java 日志分析器",
    version="0.1.0",
)


@app.get("/health")
def health():
    return {
        "status": "UP",
        "service": "log-analyzer",
    }


@app.post(
    "/api/v1/logs/analyze",
    response_model=LogAnalyzeResponse,
)
def analyze_log_api(request: LogAnalyzeRequest):
    try:
        result = analyze_log(request.log_text)

        warnings = validate_analysis(result)
        business_warnings = validate_business_rules(result)

        all_warnings = warnings + business_warnings

        message = "分析成功"
        if all_warnings:
            message = "分析完成，但存在质量提醒：" + "；".join(all_warnings)

        return LogAnalyzeResponse(
            success=True,
            data=result,
            message=message,
        )

    except Exception as exc:
        raise HTTPException(
            status_code=500,
            detail=f"日志分析失败：{exc}",
        )
```

# 五、今天的小练习

## 练习 1：测试参数校验

分别发送这些请求。

### 空日志

```json
{
  "log_text": ""
}
```

**返回结果：** 返回为422，提示"msg": "String should have at least 1 character"

### 缺少字段

```json
{}
```

**返回结果：** 返回为422，提示"msg": "Field required"

### 超长日志

生成一段超过 10000 个字符的字符串提交。

**返回结果：** 返回为422，提示"msg": "String should have at most 1000 characters"

观察 FastAPI 返回的 **422** 响应，并回答：

```text
1. 为什么还没进入 analyze_log_api，接口就已经返回错误？

FastAPI 会在执行路由函数之前解析请求体，并根据 Pydantic 模型进行参数校验。如果请求数据不符合模型定义，就会直接返回 HTTP 422，不会进入路由函数的业务逻辑，也不会调用大模型。

2. Pydantic 在这里承担了什么职责？

Pydantic 负责校验输入数据的结构、字段是否存在、字段类型以及长度等约束，并将通过校验的数据解析为模型对象，供后续业务逻辑使用。

3. 这和 Java Controller 接收 DTO 时的参数校验有什么相似之处？

两者都可以在业务逻辑执行之前校验请求参数。例如，Java 可以使用 DTO、`@Valid` 和约束注解；FastAPI 则可以使用 Pydantic 的 `BaseModel` 和 `Field`。这样可以将参数校验与业务逻辑分离，提高代码的可维护性。

```

## 练习 2：增加批量接口

新增：

```python
class BatchLogAnalyzeRequest(BaseModel):
    logs: list[LogAnalyzeRequest]
```

再增加接口：

```python
@app.post("/api/v1/logs/analyze-batch")
def analyze_batch(request: BatchLogAnalyzeRequest):
    results = []

    for item in request.logs:
        try:
            result = analyze_log(item.log_text)
            results.append({
                "success": True,
                "data": result,
            })
        except Exception as exc:
            results.append({
                "success": False,
                "message": str(exc),
            })

    return {
        "total": len(request.logs),
        "results": results,
    }
```

测试请求：

```json
{
  "logs": [
    {
      "log_text": "HikariPool-1 - Exception during pool initialization"
    },
    {
      "log_text": "No Feign Client for loadBalancing"
    },
    {
      "log_text": "zookeeper connect timeout"
    }
  ]
}
```

这里你会看到一个很重要的工程问题：

> **批量任务中，单条失败是否应该影响全部结果？**

今天先采用：

> **单条失败、整体继续**

的策略。
