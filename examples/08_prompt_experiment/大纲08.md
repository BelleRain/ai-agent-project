# 四、今天写什么代码

在 `01-llm-api/` 下新建：

```text
prompt_experiment.py
```

先把模型调用中的 `temperature` 抽出来：

```python
import json
import os
from typing import List

from dotenv import load_dotenv
from openai import OpenAI
from pydantic import BaseModel

load_dotenv()


class ErrorAnalysis(BaseModel):
    error_type: str
    possible_causes: List[str]
    suggestions: List[str]


client = OpenAI(
    api_key=os.getenv("OPENAI_API_KEY"),
    base_url=os.getenv("OPENAI_BASE_URL"),
)


PROMPT = """
你是一名资深 Java 后端故障分析工程师。

请分析下面的错误日志，并严格返回 JSON：
{{
  "error_type": "简洁的错误类型",
  "possible_causes": ["至少 2 条可能原因"],
  "suggestions": ["至少 2 条解决建议"]
}}

要求：
1. 只返回 JSON
2. 不要输出 Markdown
3. 原因和建议必须结合日志
4. 不要给出无法从日志推断出的绝对结论

错误日志：
{log_text}
"""


def analyze_log(log_text: str, temperature: float) -> ErrorAnalysis:
    response = client.chat.completions.create(
        model=os.getenv("MODEL_NAME"),
        messages=[
            {
                "role": "system",
                "content": "你负责将 Java 错误日志转换为结构化故障分析结果。",
            },
            {
                "role": "user",
                "content": PROMPT.format(log_text=log_text),
            },
        ],
        temperature=temperature,
    )

    content = response.choices[0].message.content
    data = json.loads(content)
    return ErrorAnalysis(**data)
```

然后增加一个实验函数：

```python
def run_experiment(log_text: str) -> None:
    temperatures = [0, 0.3, 0.7, 1.0]

    for temperature in temperatures:
        print(f"\n========== temperature={temperature} ==========")

        try:
            result = analyze_log(log_text, temperature)

            print("错误类型：", result.error_type)
            print("可能原因：", result.possible_causes)
            print("解决建议：", result.suggestions)

        except Exception as exc:
            print("调用失败：", exc)


if __name__ == "__main__":
    run_experiment(
        "HikariPool-1 - Exception during pool initialization"
    )
```

### 重要提醒

不同模型服务商对 `temperature` 的支持和实际效果可能不同，有些新模型甚至可能忽略或限制该参数。

如果你的接口报错：

1. 先把 `temperature` 固定为 `0`；
2. 或者暂时移除 `temperature` 参数；
3. 不要在这里浪费太多时间。

今天的重点是理解**实验方法**，而不是解决某个模型参数兼容问题。

## 练习 1：比较 4 组参数

分别运行：

```text
temperature = 0
temperature = 0.3
temperature = 0.7
temperature = 1.0
```

观察以下内容：

* `error_type` 是否变化
* `possible_causes` 的条数是否变化
* `suggestions` 是否出现重复或泛化
* 是否出现格式不稳定

把结果记录到：

```text
day08_experiment.md
```

建议使用下面的表格：

```markdown
| temperature | 错误类型 | 原因是否具体 | 建议是否重复 | JSON是否稳定 |
|---|---|---|---|---|
| 0.0 |  |  |  |  |
| 0.3 |  |  |  |  |
| 0.7 |  |  |  |  |
| 1.0 |  |  |  |  |
```

## 练习 2：同一个温度重复运行 3 次

固定：

```text
temperature = 0.3
```

对同一条日志连续运行 3 次，记录：

* 输出是否完全一致
* 差异发生在哪些字段
* 哪种差异是可以接受的
* 哪种差异会影响业务使用

这个练习要理解：

> **“低随机性”不等于“绝对一致”，而“结构稳定”也不等于“内容正确”。**
