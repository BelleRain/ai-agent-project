# 四、今天的核心代码

文件：

```text
batch_log_analyzer.py
```

代码：

```python
import json
import os
from typing import List

from dotenv import load_dotenv
from openai import OpenAI
from pydantic import BaseModel, ValidationError

load_dotenv()


class ErrorAnalysis(BaseModel):
    error_type: str
    possible_causes: List[str]
    suggestions: List[str]


client = OpenAI(
    api_key=os.getenv("OPENAI_API_KEY"),
    base_url=os.getenv("OPENAI_BASE_URL"),
)


PROMPT_TEMPLATE = """
你是一名资深 Java 后端故障分析工程师。

请分析下面的错误日志，并严格返回合法 JSON：
{{
  "error_type": "字符串",
  "possible_causes": ["字符串"],
  "suggestions": ["字符串"]
}}

要求：
1. error_type 必须简洁
2. possible_causes 至少返回 2 条
3. suggestions 至少返回 2 条
4. 不要输出 Markdown
5. 不要输出额外说明

错误日志：
{log_text}
"""


def analyze_log(log_text: str) -> ErrorAnalysis:
    prompt = PROMPT_TEMPLATE.format(log_text=log_text)

    response = client.chat.completions.create(
        model=os.getenv("MODEL_NAME"),
        messages=[
            {
                "role": "system",
                "content": "你负责将 Java 错误日志转换为结构化故障分析结果。",
            },
            {
                "role": "user",
                "content": prompt,
            },
        ],
        temperature=0,
    )

    content = response.choices[0].message.content

    try:
        data = json.loads(content)
        return ErrorAnalysis(**data)
    except json.JSONDecodeError as exc:
        raise ValueError(f"返回结果不是合法 JSON：{content}") from exc
    except ValidationError as exc:
        raise ValueError(f"返回结果字段不符合要求：{content}") from exc


def analyze_logs(logs: List[str]) -> List[ErrorAnalysis]:
    results = []

    for index, log_text in enumerate(logs, start=1):
        print(f"\n正在分析第 {index} 条日志...")
        try:
            result = analyze_log(log_text)
            results.append(result)
        except Exception as exc:
            print(f"分析失败：{exc}")

    return results


def print_summary(results: List[ErrorAnalysis]) -> None:
    print("\n========== 分析汇总 ==========")

    for index, result in enumerate(results, start=1):
        print(f"\n[{index}] {result.error_type}")

        print("可能原因：")
        for cause in result.possible_causes:
            print(" -", cause)

        print("解决建议：")
        for suggestion in result.suggestions:
            print(" -", suggestion)


if __name__ == "__main__":
    logs = [
        "HikariPool-1 - Exception during pool initialization",
        "No Feign Client for loadBalancing",
        "zookeeper connect timeout",
        "NettyRemotingServer bind fail",
    ]

    results = analyze_logs(logs)
    print_summary(results)
```

# 五、代码结构理解

今天不要只是把代码运行起来，要理解整个调用链。

```text
logs
 ↓
analyze_logs()
 ↓
逐条调用
 ↓
analyze_log()
 ↓
Prompt 模板 + 日志
 ↓
LLM
 ↓
JSON 字符串
 ↓
json.loads()
 ↓
ErrorAnalysis
 ↓
print_summary()
```

对应职责：

| 模块                    | 负责什么                    |
| --------------------- | ----------------------- |
| Prompt                | 告诉模型应该如何分析              |
| LLM                   | 理解日志、生成分析结果             |
| `json.loads()`        | 将 JSON 字符串转换为 Python 数据 |
| `ErrorAnalysis`       | 校验结果结构                  |
| `analyze_log()`       | 完成单条日志分析                |
| `analyze_logs()`      | 批量处理                    |
| `print_summary()`     | 输出结果                    |
| `count_error_types()` | 统计结果                    |

# 九、理解这一步为什么重要

这里开始出现一个非常重要的 AI 应用开发思想：

```text
                    ┌─────────────┐
                    │     LLM     │
                    │             │
                    │ 理解日志     │
                    │ 提取信息     │
                    │ 生成分析     │
                    └──────┬──────┘
                           │
                           ↓
                    结构化结果
                           │
                           ↓
                    ┌─────────────┐
                    │   Python    │
                    │             │
                    │ 统计         │
                    │ 判断         │
                    │ 保存         │
                    │ 调用其他系统  │
                    └─────────────┘
```

不要把所有事情都交给 LLM。

更合理的方式是：

> **LLM 擅长理解和生成，传统代码负责确定性的业务逻辑。**

例如：

```text
LLM：
“这条日志大概率属于数据库连接异常。”

Python：
“数据库连接异常出现了 37 次。”

Python：
“超过 20 次，触发告警。”

Python：
“生成日报。”

Python：
“写入数据库。”
```

这正是后面开发 Agent、AI 应用时非常重要的思路。

## 2. List

```text

```

例如：

```python

    "error 1",
    "error 2",
    "error 3"
]
```

---

## 3. Pydantic BaseModel

```python
class ErrorAnalysis(BaseModel):
    error_type: str
    possible_causes: List[str]
    suggestions: List[str]
```

可以把它暂时理解成：

> Python 里的一个 DTO / 数据模型。

这和你熟悉的 Java：

```java
public class ErrorAnalysis {

    private String errorType;

    private List<String> possibleCauses;

    private List<String> suggestions;
}
```

非常类似。

---

## 4. 异常处理

```python
try:
    ...
except Exception as exc:
    ...
```

今天尤其要理解：

```python
for log in logs:
    try:
        analyze_log(log)
    except Exception:
        continue
```

为什么不能因为：

```text
第 3 条日志分析失败
```

就导致：

```text
第 1、2、4、5 条日志全部无法处理
```

这就是批处理程序和单条脚本之间的重要区别。
