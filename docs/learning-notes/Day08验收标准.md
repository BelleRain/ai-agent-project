## 四、核心能力验收

不要求背诵定义，能够结合今天的 Java 错误日志分析器回答以下问题即可。

### 问题 1：为什么 temperature 相同，输出仍然可能不同？

**验收要求：** 能说明 temperature 影响生成行为，但不保证输出完全一致；实际结果还会受到模型及服务实现等因素影响。

**答：** temperature 会影响模型生成内容时的随机性，但不能保证输出完全一致。即使参数相同，多次调用也可能因为模型及服务实现等因素产生不同的结果。

### 问题 2：为什么宽松 Prompt 返回了 JSON，程序仍然报错？

**验收要求：** 能解释 JSON 可以被解析，不代表字段满足 `ErrorAnalysis` 的要求。 当前错误是缺少 `possible_causes` 和 `suggestions` 两个必填字段。

**答：** 因为JSON格式正确不代表字段符合程序要求。我的 ErrorAnalysis 定义了 error_type、possible_causes 和 suggestions 三个必填字段，但宽松 Prompt 返回的数据缺少 possible_causes 和 suggestions，因此 Pydantic 校验失败。

### 问题 3：严格 Prompt 为什么更适合当前日志分析器？

**验收要求：** 能说明严格 Prompt 明确规定字段和内容要求，更容易让模型输出符合程序预期的数据。

**答：** 严格Prompt明确规定了返回字段、内容要求和输出格式，能够更好地约束模型的输出，使结果更符合程序预期，适合批量处理Java错误日志。

### 问题 4：Pydantic 校验通过，是否代表模型分析正确？

**验收要求：** 明确回答“不代表”。Pydantic 主要检查数据结构和类型，不能单独证明故障原因和解决建议符合实际情况。

**答：** 不代表。Pydantic 主要检查数据结构、必填字段和数据类型是否符合要求，不能保证模型分析出的故障原因正确，也不能保证解决建议适用于实际场景。

### 问题 5：如何判断一次 Prompt 修改是否有效？

**验收要求：** 能提出使用固定测试样例、比较修改前后的输出，并从分类合理性、原因准确性、建议可执行性和结构合规性等方面进行评估。

**答：** 使用固定的测试样例，分别运行修改前后的Prompt，从错误分类是否合理、原因是否准确、建议是否可执行、输出结构是否符合要求等方面进行比较，而不是只根据一次输出判断效果。

## 六、今日学习总结

请用自己的话补全下面 5 句话：

1. `temperature` 的作用是：________。
2. 相同参数重复调用，结果仍然可能不同，因为：________。
3. 严格 Prompt 相比宽松 Prompt 的优势是：________。
4. Pydantic 校验通过不代表业务正确，因为：________。
5. 以后开发调度运维 Agent 时，我会通过________来验证模型输出是否满足业务要求。

**答：**

1. `temperature` 的作用是：影响模型生成内容时的随机性，从而影响输出的多样性，但不直接保证输出质量。
2. 相同参数重复调用，结果仍然可能不同，因为： 模型生成过程可能存在随机性，不能模型以及服务实现也可能影响输出结果。
3. 严格 Prompt 相比宽松 Prompt 的优势是：明确规定输出字段和内容要求，使模型更容易生成符合程序预期的数据。
4. Pydantic 校验通过不代表业务正确，因为：它主要验证数据结构和类型，不能判断故障分析是否准确，解决建议是否合理。
5. 以后开发调度运维 Agent 时，我会通过 **固定测试集、多次重复测试、输出结构校验和业务效果评估** 来验证模型输出是否满足业务要求。
