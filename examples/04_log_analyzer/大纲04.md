## 五、log_analyzer.py

```python
import json
import os

from dotenv import load_dotenv
from openai import OpenAI
from pydantic import BaseModel, ValidationError

load_dotenv()


class ErrorAnalysis(BaseModel):
    error_type: str
    possible_causes: list[str]
    suggestions: list[str]


client = OpenAI(
    api_key=os.getenv("OPENAI_API_KEY"),
    base_url=os.getenv("OPENAI_BASE_URL"),
)


def analyze_log(log_text: str) -> ErrorAnalysis:
    response = client.chat.completions.create(
        model=os.getenv("MODEL_NAME"),
        messages=[
            {
                "role": "system",
                "content": (
                    "你是一名资深 Java 后端故障分析工程师。"
                    "只返回合法 JSON，不要输出 Markdown 代码块。"
                ),
            },
            {
                "role": "user",
                "content": f"""
请分析下面的错误日志，并严格返回 JSON：
{{
  "error_type": "字符串",
  "possible_causes": ["字符串"],
  "suggestions": ["字符串"]
}}

错误日志：
{log_text}
""",
            },
        ],
    )

    content = response.choices[0].message.content

    try:
        data = json.loads(content)
        return ErrorAnalysis(**data)

    except json.JSONDecodeError as exc:
        raise ValueError(
            f"模型返回的内容不是合法 JSON：{content}"
        ) from exc

    except ValidationError as exc:
        raise ValueError(
            f"模型返回字段不符合要求：{content}"
        ) from exc


def print_analysis(result: ErrorAnalysis) -> None:
    print("错误类型：", result.error_type)

    print("\n可能原因：")
    for cause in result.possible_causes:
        print("-", cause)

    print("\n解决建议：")
    for suggestion in result.suggestions:
        print("-", suggestion)


if __name__ == "__main__":
    log_text = input("请输入错误日志：")

    try:
        result = analyze_log(log_text)
        print_analysis(result)

    except Exception as exc:
        print("分析失败：", exc)
```

# 六、代码重点理解

今天不要只追求“代码能运行”，需要理解这段代码为什么这样写。

## 1. Pydantic 定义返回结构

```python
class ErrorAnalysis(BaseModel):
    error_type: str
    possible_causes: list[str]
    suggestions: list[str]
```

可以把它理解成 Java 中的 DTO：

```java
public class ErrorAnalysis {

    private String errorType;

    private List<String> possibleCauses;

    private List<String> suggestions;
}
```

它规定了我们希望模型最终返回的数据结构。

---

## 2. LLM 调用封装成函数

```python
def analyze_log(log_text: str) -> ErrorAnalysis:
```

这个函数完成：

```text
输入日志
   ↓
调用 LLM
   ↓
获取模型返回内容
   ↓
JSON 解析
   ↓
Pydantic 校验
   ↓
返回 ErrorAnalysis
```

以后其他程序只需要：

```python
result = analyze_log(log_text)
```

就可以复用这个能力。

这就是今天非常重要的一个工程化思维：

> 不要把 LLM 调用代码散落在业务代码里，而是把它封装成一个可以复用的函数。

---

## 3. JSONDecodeError

```python
data = json.loads(content)
```

这里存在一种情况：

模型说自己返回 JSON，但实际上可能返回：

```text
这是分析结果：

{
    "error_type": "数据库连接异常"
}
```

这并不是一个可以直接被 `json.loads()` 解析的纯 JSON。

因此：

```python
except json.JSONDecodeError:
```

负责处理：

> 模型返回内容不是合法 JSON。

---

## 4. ValidationError

即使 JSON 格式正确，也不代表数据符合我们的业务要求。

例如模型返回：

```json
{
  "error_type": "数据库连接异常",
  "possible_causes": [
    "数据库连接失败"
  ]
}
```

JSON 本身是合法的。

但是：

```text
suggestions
```

字段缺失。

这时候：

```python
ErrorAnalysis(**data)
```

会触发：

```python
ValidationError
```

所以需要：

```python
except ValidationError:
```

处理。

# 八、今天需要特别理解的异常层次

今天实际上是在建立一个非常重要的思维：

```text
                LLM API
                   │
                   ↓
             API 调用异常
                   │
                   ↓
             获取返回内容
                   │
                   ↓
             JSON 格式校验
                   │
             ┌─────┴─────┐
             ↓           ↓
          合法 JSON    非法 JSON
             │           │
             ↓           ↓
        Pydantic      JSONDecodeError
          校验
             │
       ┌─────┴─────┐
       ↓           ↓
    校验通过     字段异常
       │           │
       ↓           ↓
   返回 DTO    ValidationError
```

这个过程和 Java 后端处理第三方服务返回结果非常相似。
