# Week 1 Review｜第一周学习复盘

## 1. OpenAI API 调用的基本流程是什么？

首先创建 OpenAI `client` 客户端对象，通过 `client.chat.completions.create()` 调用模型，并通过 `messages` 传入 system prompt 和 user prompt。模型返回响应后，程序提取生成的内容，再进行 JSON 解析、Pydantic 校验和业务检查，最终得到日志分析结果。

## 2. system prompt 和 user prompt 有什么区别？

System prompt 用于规定模型的角色、行为和输出约束，例如要求模型扮演 Java 日志分析助手，并按照指定的字段返回结果，主要解决模型应该怎么做的问题。User prompt 用于提供具体任务和输入，例如要求分析 `HikariPool-1 - Exception during pool initialization` 这条日志，主要解决模型这次需要做什么的问题。

## 3. JSON 字符串和 Pydantic 对象有什么区别？

JSON 字符串是符合 JSON 语法的文本，可以用于数据传输和存储，例如模型返回的错误类型、可能原因和解决建议。Pydantic 对象是根据 `ErrorAnalysis` 模型创建的 Python 对象，可以通过属性访问字段，并对数据类型、必填字段等进行校验。在日志分析器中，可以将模型返回的 JSON 解析并校验为 Pydantic 对象，再进行后续评分和业务处理。

## 4. 为什么要捕获 JSONDecodeError 和 ValidationError？

`JSONDecodeError` 表示 JSON 解析失败，例如模型返回了普通文本、JSON 语法错误或不完整的 JSON。`ValidationError` 表示数据未通过 Pydantic 模型校验，例如缺少必填字段、字段类型不匹配，或者不满足指定的校验规则。在日志分析器中捕获这两类异常，可以定位不同阶段的问题，避免单条异常输出导致程序无法正常处理后续日志。

## 5. 为什么模型结果还需要评分和业务校验？

模型结果需要评分和业务校验，因为格式正确、结构正确并不代表业务内容可靠。评分用于根据预先定义的指标评估结果质量，例如原因和建议是否为空、建议数量是否合理；业务校验用于检查结果是否满足具体业务规则，例如错误类型是否合理、建议是否与日志场景相关。两者能够帮助发现低质量结果，但不能完全保证模型分析结论一定正确，必要时仍需要结合原始日志、异常堆栈和实际运行环境进行验证。

## 第一周核心知识总结

| 层次 | 含义 | 日志分析器中的示例 |
|---|---|---|
| API 调用 | 向模型发送请求并获取响应 | 调用 `client.chat.completions.create()` |
| JSON 解析 | 将 JSON 文本解析为数据 | 检查返回内容是否符合 JSON 语法 |
| 结构校验 | 检查数据是否符合模型定义 | 校验 `ErrorAnalysis` 的字段 |
| 业务校验 | 检查内容是否满足业务规则 | 判断原因和建议是否与日志场景相关 |
| 结果评分 | 根据质量指标评估分析结果 | 检查原因和建议是否为空、数量是否合理 |

**本周核心认知：**

格式正确不代表结构正确，结构正确也不代表业务正确。AI 应用不仅需要调用模型，还需要通过解析、结构校验、业务校验和质量评估，提高输出结果的可用性与可靠性。
