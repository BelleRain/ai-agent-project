# Day 10｜原生 Structured Output：从手写 `json.loads()` 过渡到 Schema 约束

今天是 **2026 年 9 月 10 日，周四**。继续 9 月阶段，今天只推进一个关键升级：

> 把前几天“让模型返回 JSON，再手动 `json.loads()`”的方式，升级为**由 API 原生约束结构，并直接解析成 Pydantic 对象**。

这一步很重要，因为在真实 AI 应用里，Prompt 里写“请返回 JSON”远远不够；你需要把结构定义交给 API，并对拒答、截断、字段内容错误等情况做处理。

OpenAI 的 Structured Outputs 支持通过 JSON Schema 约束响应结构，也支持在工具定义中使用 `strict: true`。

# 三、今天要掌握什么

今天只记住这条链路：

```text
Pydantic Model
      ↓
JSON Schema
      ↓
API 原生约束
      ↓
直接解析为对象
      ↓
业务校验
```

你还要理解下面三个层次的区别：

```text
普通文本：
模型自由输出

JSON Mode：
保证尽量是合法 JSON

Structured Outputs：
按 Schema 约束字段、类型和结构
```

但要注意：

```text
结构正确 ≠ 内容正确
```

例如：

```json
{
  "error_type": "数据库连接异常",
  "possible_causes": [
    "数据库连接池耗尽"
  ],
  "suggestions": [
    "检查数据库连接池配置"
  ]
}
```

这个结果可能完全符合 Schema，但：

```text
possible_causes 只有 1 条
suggestions 只有 1 条
```

如果你的业务要求至少提供 2 条原因和 2 条建议，那么它仍然是不合格的。

因此：

> **Schema 负责“结构正确”，业务校验负责“业务正确”。**

## 2. 改造 `log_analyzer.py`

今天建议使用 SDK 的 Pydantic 解析方式。

新建或覆盖为：

```python
from openai import OpenAI
from pydantic import BaseModel
from dotenv import load_dotenv
import os

load_dotenv()


class ErrorAnalysis(BaseModel):
    error_type: str
    possible_causes: list[str]
    suggestions: list[str]


client = OpenAI(
    api_key=os.getenv("OPENAI_API_KEY"),
    base_url=os.getenv("OPENAI_BASE_URL"),
)


SYSTEM_PROMPT = """
你是一名资深 Java 后端故障分析工程师。
请根据错误日志，给出简洁、可执行、基于证据的故障分析。
如果无法确定，请明确说明需要进一步确认。
"""


def analyze_log(log_text: str) -> ErrorAnalysis:
    response = client.beta.chat.completions.parse(
        model=os.getenv("MODEL_NAME"),
        messages=[
            {
                "role": "system",
                "content": SYSTEM_PROMPT,
            },
            {
                "role": "user",
                "content": f"请分析下面的错误日志：\n{log_text}",
            },
        ],
        response_format=ErrorAnalysis,
        temperature=0,
    )

    message = response.choices[0].message

    if getattr(message, "refusal", None):
        raise ValueError(f"模型拒答：{message.refusal}")

    if message.parsed is None:
        raise ValueError("模型没有返回可解析的结构化结果")

    return message.parsed
```

## 3. 保留业务校验

在 `prompt_eval.py` 中继续使用：

```python
from models import ErrorAnalysis


def validate_analysis(result: ErrorAnalysis) -> list[str]:
    warnings = []

    if len(result.possible_causes) < 2:
        warnings.append("可能原因少于 2 条")

    if len(result.suggestions) < 2:
        warnings.append("解决建议少于 2 条")

    if len(result.error_type.strip()) < 3:
        warnings.append("错误类型过短")

    return warnings
```
