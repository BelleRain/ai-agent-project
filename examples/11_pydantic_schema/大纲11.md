## 今天要掌握什么

今天重点掌握下面 4 个概念：

1. `Literal / Enum`：限制字段只能取固定值
2. 嵌套对象：让复杂结果有层次
3. `Field`：为字段添加描述和约束
4. Schema 约束 ≠ 业务判断，业务校验仍然要保留

对应到 Java 后端，你可以这样理解：

```text
Pydantic BaseModel  ≈ DTO
Literal / Enum      ≈ Java Enum
Field               ≈ 字段说明 + 校验元数据
嵌套 Model          ≈ 嵌套对象
model_validate      ≈ 参数绑定与校验
```

# 今天写什么代码

今天把 `models.py` 改成下面这样：

```python
from typing import Literal

from pydantic import BaseModel, Field


class Evidence(BaseModel):
    log_fragment: str = Field(
        description="用于支持判断的关键日志片段"
    )
    explanation: str = Field(
        description="说明该日志片段为什么支持当前判断"
    )


class ErrorAnalysis(BaseModel):
    error_type: str = Field(
        description="简洁的错误类型，例如数据库连接失败"
    )
    severity: Literal["low", "medium", "high"] = Field(
        description="问题严重程度"
    )
    confidence: Literal["low", "medium", "high"] = Field(
        description="模型对当前判断的置信度"
    )
    possible_causes: list[str] = Field(
        min_length=1,
        description="可能原因列表"
    )
    suggestions: list[str] = Field(
        min_length=1,
        description="解决建议列表"
    )
    evidence: list[Evidence] = Field(
        min_length=1,
        description="支撑判断的证据"
    )
```

这里新增了：

* `severity`：严重程度
* `confidence`：模型置信度
* `evidence`：证据列表
* `Literal`：固定枚举值
* `Evidence`：嵌套对象

## 修改 Prompt

在 `prompts.py` 中改成：

```python
SYSTEM_PROMPT = """
你是一名资深 Java 后端故障分析工程师。

请根据错误日志进行保守分析：
1. 只能基于日志内容推断
2. 无法确认时，confidence 输出 low
3. 必须给出支持判断的日志证据
4. 不要编造日志中不存在的信息
"""
```

用户提示词改成：

```python
USER_PROMPT_TEMPLATE = """
请分析下面的 Java 错误日志，并返回结构化结果。

要求：
1. error_type：简洁描述错误类型
2. severity：只能是 low、medium、high
3. confidence：只能是 low、medium、high
4. possible_causes：至少返回 2 条可能原因
5. suggestions：至少返回 2 条可执行建议
6. evidence：至少返回 1 个证据对象
7. evidence.log_fragment 必须引用输入日志中的原文或关键片段
8. 无法确认时，必须降低 confidence
9. 不要输出 Markdown
10. 不要输出额外解释

错误日志：
{log_text}
"""
```

```python

```

那么只需要让 `response_format` 继续使用新的 `ErrorAnalysis` 即可：

```python
response = client.beta.chat.completions.parse(
    model=settings.model_name,
    messages=[
        {
            "role": "system",
            "content": SYSTEM_PROMPT,
        },
        {
            "role": "user",
            "content": USER_PROMPT_TEMPLATE.format(

    response_format=ErrorAnalysis,

message = response.choices[0].message

    raise ValueError(f"模型拒答：{message.refusal}")

    raise ValueError("模型没有返回结构化结果")

return message.parsed
```

## 练习 2：故意制造 Schema 错误

将 Prompt 中的要求改成：

```text
severity 只能输出 critical
```

但保留 Pydantic 定义：

```python
Literal["low", "medium", "high"]
```

观察模型返回时会不会出现解析失败，或者服务端直接拒绝。

这个实验是为了理解：

> **Schema 越严格，错误越早暴露。**

## 练习 3：增加一个业务校验函数

在 `prompt_eval.py` 中新增：

```python
from models import ErrorAnalysis


def validate_business_rules(result: ErrorAnalysis) -> list[str]:
    warnings = []

    if result.confidence == "low" and result.severity == "high":
        warnings.append(
            "严重程度较高，但模型置信度较低，需要人工确认"
        )

    if len(result.evidence) == 0:
        warnings.append("缺少证据")

    for item in result.evidence:
        if not item.log_fragment.strip():
            warnings.append("存在空的日志证据")

    return warnings
```

然后在 `cli.py` 中输出：

```python
business_warnings = validate_business_rules(result)

if business_warnings:
    print("\n业务校验提醒：")
    for warning in business_warnings:
        print("-", warning)
```

这里要注意：

```text
Pydantic 负责结构合法
业务函数负责业务合理
```
