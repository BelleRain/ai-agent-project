## 三、Python 核心语法验收

### 问题 1：Python 中的 `or` 是什么意思？

回答应包含：

- `or` 是逻辑或运算符。
- 从左向右判断，左侧为真值时直接返回左侧，不再计算右侧。
- 左侧为假值时返回右侧。
- `None`、`False`、`0`、空字符串、空列表等都属于假值。

示例：

```python
version = prompt_version or settings.prompt_version
```

表示优先使用传入的 Prompt 版本；如果没有传入有效值，则使用系统默认版本。

### 问题 2：下面的代码是什么意思？

```python
keyword_hits = sum(
    1 for keyword in expected_keywords
    if keyword.lower() in text.lower()
)
```

回答应包含：

- `for keyword in expected_keywords` 遍历关键词列表。
- `if` 对每个关键词进行条件判断。
- `keyword.lower()` 将关键词转换为小写。
- `in` 判断字符串是否包含指定内容。
- `sum()` 对每次命中的 1 进行累加，最终得到命中关键词的数量。

### 问题 3：`any()` 函数的作用是什么？

回答应包含：

- `any()` 是 Python 内置函数。
- 只要可迭代对象中存在一个 True，就返回 True。
- 如果全部为 False，则返回 False。
- 如果可迭代对象为空，则返回 False。
- `any()` 具有短路特性，找到第一个 True 后就停止遍历。

示例：

```python
any([False, True, False])  # True
any([False, False, False]) # False
```

### 问题 4：下面的代码是什么语法？

```python
any(
    keyword.lower() in evidence_text.lower()
    for keyword in expected_keywords
)
```

回答应包含：

- 这是生成器表达式。
- 基本语法为 `(表达式 for 变量 in 可迭代对象)`。
- `for` 后面是遍历对象和循环变量。
- `for` 前面是每次循环需要执行的表达式。
- 生成器表达式不会像列表推导式一样立即创建完整列表。
- 配合 `any()` 使用时，可以逐个判断关键词，并在找到 True 后停止。

### 问题 5：生成器表达式和列表推导式有什么区别？

回答应包含：

```python
# 生成器表达式
result = (x * 2 for x in numbers)

# 列表推导式
result = [x * 2 for x in numbers]
```

- 生成器表达式使用圆括号，返回生成器对象，按需产生元素。
- 列表推导式使用方括号，立即生成列表。
- 两者都可以简化普通 for 循环。

### 问题 6：`any()` 和 `sum()` 在关键词评估中有什么区别？

回答应包含：

| 函数 | 作用 | 返回值 |
|---|---|---|
| `any()` | 判断是否至少命中一个关键词 | bool |
| `sum()` | 统计命中关键词的数量 | int |

示例：

```python
# 判断是否命中
matched = any(
    keyword.lower() in text.lower()
    for keyword in expected_keywords
)

# 统计命中数量
keyword_hits = sum(
    1 for keyword in expected_keywords
    if keyword.lower() in text.lower()
)
```

## 四、核心知识理解验收

### 问题 1：为什么 Prompt 需要版本管理？

回答应包含：

- Prompt 会影响模型输出结果。
- 修改 Prompt 可能改善某些场景，也可能破坏已有场景。
- 版本管理可以追踪 Prompt 的修改历史。
- 能够比较不同版本的效果。
- 出现问题时可以回滚到之前的稳定版本。

### 问题 2：为什么 A/B 测试必须固定输入？

回答应包含：

- 不同 Prompt 必须使用相同的测试数据。
- 避免输入差异影响评估结果。
- 确保评分差异主要来自 Prompt 版本变化。
- 提高实验结果的可比性和可信度。

### 问题 3：Prompt v2 比 v1 增加了哪些约束？

回答应包含：

- 明确要求返回结构化 JSON。
- 明确规定字段名称。
- 明确规定字段类型。
- 明确规定字段数量和内容要求。
- 限制模型只能按照约定结构输出。

### 问题 4：为什么 Structured Output 不能替代 Prompt？

回答应包含：

- Structured Output 主要约束输出格式和字段结构。
- Prompt 负责告诉模型应该分析什么、如何分析以及遵循哪些业务规则。
- 格式正确不代表分析结论正确。
- 两者配合才能提高输出的稳定性和可用性。

### 问题 5：线上排查时，为什么要记录 model_name 和 prompt_version？

回答应包含：

- 不同模型可能产生不同结果。
- 不同 Prompt 版本可能影响分析质量。
- 记录模型和 Prompt 版本可以还原当时的调用环境。
- 便于定位问题、复现问题和比较分析结果。

### 问题 6：为什么评分规则本身也需要验证？

回答应包含：

- 评分代码决定模型输出是否通过验收。
- 评分条件错误可能导致正确结果被判定为失败。
- 评分标准必须与业务要求保持一致。
- 应通过边界测试验证评分逻辑，避免评估结果失真。
