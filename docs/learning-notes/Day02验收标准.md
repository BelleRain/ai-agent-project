今日目标：
System Prompt：规定模型的身份、规则和输出要求
User Prompt：本次具体任务和输入数据
Few-shot：给模型看少量输入/输出示例
Structured Output：让模型返回固定 JSON 结构

理解核心：
普通提问：模型自由回答
结构化要求：模型输出可以被程序继续处理的数据


验收标准
1.能说明 `system` 和 `user` 的区别
2.能让模型按固定角色回答
3.能让模型输出固定字段
4.能用 3 条日志测试结果


总结：
① 理解 system 和 user
system = 规定模型的角色、行为方式和约束 （你是谁？该怎么做？）
user = 提供当前具体任务、问题和输入 （具体要做什么？）
（system 不等于 “知识库检索范围”）

② 能通过 System Prompt 设置模型角色
例如： 你是一名资深 Java 后端故障分析工程师
并能观察到模型回答风格会受到这个角色和规则的影响。

③ 能通过 Prompt 要求固定输出结构
例如：
{
    "error_type": "...",
    "possible_causes": [],
    "suggestions": []
}
并理解：
    当前只是通过Prompt要求模型输出这种结构，还不是严格意义上的Schema校验。

④用3条不同的日志测试
例如：
HikariPool-1 - Exception during pool initialization
Communications link failure
Unable to connect to any servers

验证：
不同输入
   ↓
不同分析内容
   ↓
相同输出结构

也就是：
    内容应该随着日志变化，但JSON字段结构应该保持一致。

⑤ 能解释“自由输出” 和 “结构化输出” 的区别 （Day02 最重要）
自由输出：
    模型面向人进行解释，可以自由组织内容，
    信息丰富，但程序不容易直接处理。
结构化输出：
    模型按照预先规定的字段返回数据，
    内容受到结构约束，但程序更容易解析和继续处理。

Day02 回答以下5个问题：
① 理解system 和 user 的区别
system 规定模型的角色、行为和约束（你是谁？该怎么做？）；user 提供当前具体任务和输入（具体要做什么？）。
② system 能不能直接让模型去查询数据库
不能。它只能告诉模型应该怎么做；真正查询数据库需要程序，Tooling Calling、RAG等机制。
③ 为什么同一个日志，JSON输出比自由回答简洁？
因为输出被限制在预先定义的字段和结构中，而自由回答可以自由扩展。
④三条日志测试时，什么应该相同，什么应该不同？
字段结构应该相同；分析内容应该根据不同日志而变化。
⑤JSON输出为什么对Agent有用？
因为程序可以读取结构化结果，根据其中的字段决定下一步执行什么操作。
